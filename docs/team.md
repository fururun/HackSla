# チーム体制（役割分担）

人間1人（ふるるん）と4つのAIで、ゲーム開発の職種を分担します。
AIは「面白いか」を判断できないので、方向決めと試遊は必ず人間が行います。

| 職種 | 担当 | やること |
| --- | --- | --- |
| ディレクター | ふるるん | 何を作るか、面白いかの最終判断。発注一覧のOK。試遊して方向を決める |
| PM | Claude | タスクの切り分け、指示書（`tasks/`）、発注一覧と検収結果の報告、進み具合の管理 |
| プランナー | Claude ＋ Gemini社（Antigravity） | 仕様は Claude。数値設計・バランス・参考作の調査は Gemini社 |
| プログラマー | Codex ＋ Claude | 機能の実装は Codex。中核の仕組み（スキル実行・ダメージ・ツリー）は Claude |
| デザイナー（アート） | ふるるん ＋ Muse Image ＋ pixelfx | 方向性は後で決める。下書きは Muse Image、エフェクトは pixelfx、仕上げと採用はふるるん |
| サウンド | 未定 | 後で決める |
| QA | 自動テスト ＋ 相互チェック ＋ ふるるん | 下の「QAの流れ」 |
| 広報 | Muse（下書き）＋ ふるるん | プロトタイプの後に始める |
| 情報集め | Muse（アプリ） | X などの投稿を要約し、元のリンク付きで Claude に渡す |

## 各AIの動かし方

| AI | 動かし方 |
| --- | --- |
| Claude | ふるるんとの会話（Claude Code のセッション）で直接作業する。配布スクリプトでは配らない |
| Codex | PCの配布スクリプトから `codex exec` で動かす |
| Gemini社 | PCの配布スクリプトから Antigravity CLI（`agy`）で動かす |
| Muse | アプリで手作業（`tasks/manual/` の依頼文を貼る）。配布スクリプトでは配らない |

## QAの流れ（1タスクごと）

1. **自動テスト**：書いたAIが `tests/run_tests.gd` を実行してから納品する
2. **相互チェック**：書いたAIとは別のAIが確認する（`tools/dispatch/crossreview.sh`）
   - Codex が書いたもの → Gemini社 が確認
   - Gemini社・Claude が書いたもの → Codex が確認
   - 確認する内容：テストが通るか、`allowed` の外を触っていないか、AGENTS.md のルール、指示書の完了の条件、`docs/concept.md` の「やらないこと」
3. **検収**：Claude が自分でもテストを実行し、相互チェックの結果と合わせてマージか差し戻しを決める（`review.sh`）
4. **試遊**：プロトタイプが遊べる段階ごとに、ふるるんが遊んで判断する

書いたAIは、自分の成果物を承認しない。

## 1つの波の進め方

1. Claude が指示書を書き、**発注一覧**（タスク・担当・中身）をチャットに出す
2. ふるるんがOKを出したら、配布スクリプトで配る（監視ボードで進み具合を見られる）
3. 納品されたものを相互チェック → Claude が検収し、**検収結果**をチャットに出す
4. 遊べる段階になったら、ふるるんが試遊する
