# Claude用 仕様書 ― HackSla 表示名・説明文（名前表 v0.1）

このファイルの使い方： この文書全体を Claude（ゲーム本体担当）のセッションに渡す。本文書は「表示名と説明文」の仕様であり、ゲームシステムの仕様ではない。数値・挙動の仕様は既存の指示書（claude-brief-game.md）と今後の個別ブリーフが正。

作成： Muse（モカ）／ 2026-11-07
状態： **候補集（未確定）**。ただし §2 の「暫定採用セット」は、作業を止めないための初期データとして使ってよい。最終決定はユーザーが行う。

---

## 1. Claude への指示

1. **表示名・説明文はデータファイルで定義する。** コードへの直書きはしない（既存指示書の「データ駆動」原則どおり）。表示名を変える作業が「データの差し替えだけ」で済む構造にすること。
2. **ID と表示名を分離する。** ID は英語 snake_case で安定させ、表示名（日本語）はデータ側のフィールドで持つ。表示名の変更で ID を変えないこと。
   - 推奨フィールド例： `id` / `display_name` / `reading`（読み仮名、必要なものだけ） / `description`（一行説明）
   - レアリティは順序が意味を持つので `rank`（1〜6、下から順）を必ず持つこと。
   - 装備の付与効果名は接頭辞（装備名の前に付く形容）として持つ。装備の表示名は「付与効果名＋ベース装備名」の組み立てで表示すること。
3. **§3〜§8 の候補を勝手に改名・新規作成しない。** 収まりが悪い名前があれば、書き換えずに報告で「提案」として挙げること。
4. **説明文に具体的な数値を書かない。** 数値は別フィールドで持ち、UI 側で合成する。バランス調整のたびに文章を直す構造にしないこと。
5. **スキル説明は「何が起きるか」が一読で分かる文にする。** 世界観だけのフレーバー文で効果を隠さないこと。フレーバーを足す場合は、効果説明とは別フィールド（`flavor`）に分けること。
6. 本文書にない名前が必要になった場合は、§9 の命名ルールに従って案を作り、確定扱いせず報告に含めること。

## 9. 命名ルール（今後名前を増やすときの基準）

- 既存のゲーム作品の固有名詞・造語は使わない。どこかで見たことのある名前に寄せない。
- 特定の神話・宗教・実在の地名に寄せない（世界観は未定のため、後から縛りにならない名前だけを使う）。
- 日本語のみ。短く、声に出して読みやすいことを優先する。難しい漢字には読み仮名を付ける。
- 一般的な日本語の組み合わせで作る。英語・カタカナの格好付けに逃げない。
- 説明文は一行。効果が伝わることを優先し、数値は書かない。
